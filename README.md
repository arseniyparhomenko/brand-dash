# Brand Performance Dashboard

Дашборд с правкой прямо в таблицах и автосохранением. Без билда, без npm-зависимостей.

```
index.html            вся вёрстка и логика
data/current.json     стартовые данные — нужны только при первом запуске
api/_lib.js           хранилище, сессия, проверка пароля
api/login.js          вход по паролю
api/data.js           отдаёт текущие данные
api/save.js           записывает данные
api/history.js        список версий и откат
vercel.json           заголовки: noindex
```

## Как реально заводятся данные

Настя каждый месяц собирает цифры в своём личном Клоде из скриншотов и получает HTML-артефакт — такой же дашборд, но только со своим текущим месяцем. Она присылает этот файл тебе (Омару). Дальше:

1. Ты открываешь живой дашборд → **⬆ Импорт** → выбираешь её файл.
2. Сервер разбирает файл и показывает **предпросмотр**: какой месяц новый/будет перезаписан, сколько полей в каждом разделе, что с турнирами (сколько доливает цифры в существующие, сколько создаёт новых), предупреждения (например, промо без Spend/Revenue).
3. Ты проверяешь и жмёшь «Подтвердить и залить» — только тогда данные реально уходят на сервер.
4. Новый месяц дописывается в конец, старые месяцы не трогаются. Сравнение «текущий месяц vs предыдущий» на Main Board само подхватит новый месяц — никакой правки кода не требуется.

Предпросмотр живёт 15 минут (токен в Redis с TTL) — если за это время кто-то другой успел сохранить данные вручную, коммит вежливо откажет с просьбой загрузить файл заново, а не тихо всё перепишет.

### Турниры — отдельная логика

Турнир может идти дольше одного месяца (например, «01.08–30.09»), поэтому его не заменяют целиком — сверяют **по имени** с уже существующими: если совпало, дописывают цифры за новый месяц; если не совпало — создают новую запись со своим стабильным id. Если Настя в своём Клоде слегка переименует турнир, он попадёт как новый (это видно в предпросмотре — «новых турниров: 1») — переименование или слияние строк вручную делаешь потом в обычном режиме редактирования.

### Ручная правка и автосейв — как раньше

Всё, что было: **✎ Редактировать** → пароль → правишь ячейки → автосейв через секунду. Это осталось для точечных правок/опечаток между заливками, а не как основной способ ввода данных.

### Что происходит, когда что-то идёт не так

| Ситуация | Поведение |
|---|---|
| Файл не похож на артефакт дашборда | понятная ошибка сразу в предпросмотре, ничего не сохраняется |
| Гео в файле не совпадает с нашими (`mm`/`md`) | эти данные пропускаются, показано явно |
| Кто-то сохранил данные, пока смотрели предпросмотр | коммит отказывает с просьбой загрузить файл заново |
| Предпросмотр провисел больше 15 минут | токен истёк, нужно загрузить файл ещё раз |
| Пропал интернет при ручной правке | «Не сохранилось. Повтор через 3 с» → повторяет с нарастающей паузой |
| Закрывает вкладку с несохранённым | браузер спрашивает «точно уйти?», запрос всё равно дотолкнётся |
| Сессия истекла за 12 часов | «Сессия истекла — войдите заново», правки на экране не пропадают |
| Хранилище легло | показываются данные из `data/current.json`, режим только для чтения |

Хранятся последние 40 версий (обновляются и импортом, и ручным сохранением). Откат: **⋯ → 5**.

## Развёртывание

### 1. Репозиторий и деплой

```bash
cd brand-dash
git init && git add . && git commit -m "brand dashboard"
gh repo create brand-dash --private --source=. --push
npx vercel --prod
```

Репозиторий **приватный** — в `data/current.json` внутренние цифры.

### 2. Подключить хранилище

Vercel → проект → **Storage** → Marketplace → **Upstash for Redis** → создать базу и привязать к проекту. Бесплатного тарифа хватит с огромным запасом: тут пишется один ключ размером под сотню килобайт несколько раз в месяц.

Переменные окружения Vercel подставит сам. Код принимает оба варианта именования:
`KV_REST_API_URL` / `KV_REST_API_TOKEN` либо `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`.

### 3. Пароль

Settings → Environment Variables, для Production и Preview:

| Переменная | Значение |
|---|---|
| `EDIT_PASSWORD` | `brandb3` |

После добавления переменных — **Redeploy**, иначе функции их не увидят. Это главные грабли.

### 4. Проверка

- Открыть ссылку, данные загрузились.
- **✎ Редактировать** → неверный пароль → «Пароль не подошёл».
- Верный пароль → поправить цифру → подождать секунду → «Сохранено в HH:MM» → **обновить страницу** → цифра на месте.

## Локально

Двойным кликом не откроется — нужен сервер и функции:

```bash
npx vercel dev
```

## Смена пароля

Поменять `EDIT_PASSWORD` → Redeploy. Все активные сессии при этом разлогиниваются: ключ подписи сессии выводится из пароля. В коде пароля нет.

## Первый запуск и `data/current.json`

Этот файл — только стартовый набор. Как только прошло первое сохранение, данные живут в Redis, и файл больше не читается, кроме случая, когда хранилище недоступно. Обновлять его в репозитории не нужно.

## Что осталось незакрытым

- **Просмотр открыт всем, у кого есть ссылка.** Пароль защищает запись, но не чтение. Закрывается либо Vercel Password Protection (тариф Pro), либо Basic Auth через `middleware.js`.
- В данных лежат поля, которые ни одна вкладка не показывает: `retention`, `projects`, `plans`, `vip`, `channels`, `agents`.
- У всех 113 промо пустые `spend` и `revenue` — экономика промо и ROI не считаются.
